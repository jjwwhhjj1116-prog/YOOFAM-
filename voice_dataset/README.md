# 나레이션 목소리 데이터셋 (로컬 TTS 재현용)

무협 오디오북 파이프라인의 **나레이션 음성**과 그 **대본 원문**을 짝지은 데이터셋.
로컬에서 같은 목소리를 재현(파인튜닝)하는 용도. **단일 화자 · 한국어.**

작품은 둘이지만 **나레이션 목소리는 동일인 한 명**이다(같은 ElevenLabs 목소리 클론).
그래서 전부 한 데이터셋으로 합쳐 쓴다.

## 규모

| 접두어 | 작품 | 클립 | 글자 | 원본 장면 | 자막 |
|---|---|---|---|---|---|
| (없음) | 혈마기원 1화 | 188 | 16,259 | 89 | — |
| `ep02_` | 혈마기원 2화 | 291 | 25,684 | 128 | — |
| `ng01_` | **남궁회귀 1화** | **536** | **45,692** | **283** | ✅ 283개 |
| | **합계** | **1,015** | **87,635** | 500 | |

- 총 길이 **약 3시간 5분** · 형식 **22.05 kHz · 모노 · WAV** · 514 MB
- 클립 길이: 대부분 **3~15초** (ng01 94% / ep02 95% / ep01 96%)

## 구성

```
voice_dataset/
├─ wavs/
│   ├─ narr_001_00.wav            ← 혈마기원 1화 (접두어 없음)
│   ├─ ep02_narr_001_00.wav       ← 혈마기원 2화
│   ├─ ng01_narr_001_00.wav       ← 남궁회귀 1화
│   └─ …                            (<작품>_narr_<장면번호>_<조각번호>)
├─ metadata.csv                   ← ★ 학습에 쓰는 파일 (LJSpeech)
├─ transcript.txt                 ← 사람이 읽는 목록(길이 포함)
├─ scenes/
│   ├─ ep01_narration.tsv         ← 장면 단위 텍스트 (복원본)
│   ├─ ep02_narration.tsv         ← 장면 단위 원문 (정본)
│   └─ ng01_narration.tsv         ← 장면 단위 원문 (정본)
├─ subtitles/
│   └─ ng01/
│       ├─ 001.srt … 284.srt      ← 장면별 자막 (283개)
│       └─ _index.tsv             ← 장면 / 자막줄 / 초 / 원문 대조표
└─ README.md
```

### metadata.csv — 클립 단위 라벨 (학습기가 읽는 것)

파이프(`|`) 구분 3열, LJSpeech 그대로:

```
ng01_narr_001_00|세 번째 검이 나가지 않았다. 남궁진은…|세 번째 검이 나가지 않았다. 남궁진은…
파일명(확장자 없음)|원문|정규화문
```

`wavs/` 와 `metadata.csv` 가 같은 폴더에 있으면 표준 도구가 바로 먹는다.

### subtitles/ — 자막 (SRT)

문장 단위 타임스탬프. 클립은 3~15초 덩어리라 문장 경계와 다르므로, 자기 방식으로
다시 자르거나 문장 단위 정렬이 필요할 때 쓴다.

**★ 이 SRT 는 `자막/` 폴더를 복사한 것이 아니다.** 파이프라인의 `자막/` 은 *현재
작업 중인 대본* 기준으로 다시 생성되므로, 음성을 만든 뒤 대본을 고치면 그 음성과
짝이 맞지 않는다(남궁회귀에서 실제로 199장면 중 123장면이 전혀 다른 문장이었다).
여기 들어 있는 SRT 는 **데이터셋의 그 오디오에서 직접 정렬해 만든 것**이라
글자와 음성이 일치한다. 검증 결과 **283/283 일치**.

### scenes/*.tsv — 장면 단위 원문

탭 구분 4열 — `장면 / 초 / 글자 / 나레이션 원문`. `#` 로 시작하는 머리줄 3개는 건너뛸 것.

- **`ng01` · `ep02` 는 정본** — 대본에서 그대로 꺼냈다. 초 칼럼도 채워져 있다.
- **`ep01` 은 복원본** — `오디오/` 가 다음 화로 덮어써져 대본 정본을 다시 꺼낼 수
  없었다. 클립 텍스트를 장면별로 이어 만든 것이라 클립 경계에서 공백이 하나 더
  들어갈 수 있다(내용은 동일). 초 칼럼은 비어 있다.

학습 라벨로는 `metadata.csv` 를 쓸 것. `scenes/` 와 `subtitles/` 는 보조 자료다.

## 이 데이터셋의 장점

- **텍스트가 ASR 결과가 아니라 대본 원문이다.** 음성인식 오탈자가 없는 정답 라벨.
  (오디오 분할 시각만 ASR로 잡고, 글자는 대본에서 가져왔다.)
- **단일 화자 · 단일 녹음 조건.** 대사 음성(Gemini/타입캐스트 등 다른 엔진)이 섞인
  장면은 전부 제외했다. 남궁회귀 1화는 284장면 중 순수 나레이션 283장면을 썼다.
- 거의 모든 클립이 **3~15초**라 대부분의 파인튜닝 도구에 그대로 들어간다.

## 쓰는 법

LJSpeech 형식을 그대로 받는 도구들:

- **GPT-SoVITS** — 소량 데이터에 강함. 자체 슬라이서가 있지만 이미 잘려 있으니 바로 사용
- **XTTS v2 파인튜닝** — `metadata.csv` 경로만 지정
- **F5-TTS / Piper** — 전처리 스크립트가 LJSpeech를 기본 지원

공통적으로 `wavs/` 와 `metadata.csv` 가 같은 폴더에 있으면 된다.

## 만드는 법 (다음 화 추가할 때)

저장소 루트에서, **앱의 ② TTS 제작이 완전히 끝난 뒤에** 돌린다:

```powershell
.\.venv\Scripts\python.exe _데이터셋_추가.py ng02   # 클립 + metadata
.\.venv\Scripts\python.exe _데이터셋_자막.py ng02   # 자막(오디오에서 직접 생성)
.\.venv\Scripts\python.exe _데이터셋_대본.py ng02   # 장면 단위 원문
```

### 주의 두 가지

**하나.** 세 스크립트는 작업 전후로 `오디오/.audio_texts.json` 의 지문(SHA-1)을
비교한다. 도중에 TTS가 돌아 오디오가 교체되면 **글자와 음성이 다른 버전으로
짝지어지므로**, 그걸 감지하면 `metadata.csv` 에 쓰기 전에 중단하고 그 작업이 만든
파일을 스스로 지운다. 실제로 이 사고가 한 번 났고(198장면 중 178장면 어긋남),
그래서 이 검사를 넣었다.

**둘.** `_데이터셋_만들기.py` / `_데이터셋_분할.py` 는 `voice_dataset/` 을 **처음부터
다시 만든다(덮어쓴다).** `오디오/` 는 화가 바뀌면 같은 번호로 덮어써지므로, 이전 화
클립은 이 폴더에 있는 것이 **유일한 사본**이다. 이미 쌓인 데이터셋이 있으면
반드시 `_데이터셋_추가.py` 를 쓸 것.

## 주의

- 특정 개인의 음성이다. **본인 목소리 재현 외의 용도로 쓰지 말 것.**
- 무협 낭독체라 억양이 평균적인 대화체와 다르다. 일상 대화 톤을 원하면
  그 톤의 녹음을 따로 섞어야 한다.
- 문장 경계는 ASR 정렬 기반이라 일부 클립의 앞뒤가 몇십 밀리초 잘리거나
  남을 수 있다. 학습에는 지장 없는 수준이지만, 민감한 도구면 무음 트리밍을 한 번
  돌리면 된다.
